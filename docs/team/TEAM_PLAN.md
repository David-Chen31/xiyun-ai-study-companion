# 戏韵 AI 学伴｜三人五天怎么做

第五天，请一位没参加开发的人，在演示电脑上打开一份戏曲作业。他能点第二句，从过门开始听，放慢、循环，录下自己，再分别听示范和自己的声音。关掉网页再打开，还能回到想练的那句。老师撤回作业以后，旧链接就不能继续取音频。五天的工作围绕这场演示展开。

## 每个人交什么

|人|自己负责的地方（开工时建立）|第五天拿出来的东西|怎么知道做完了|
|---|---|---|---|
|A 队长，负责让软件跑起来|backend/、数据库、启动脚本、根目录配置、共享样例 contracts/|① 能导入、打开和撤回作业的程序；② 可以从 GitHub 下载的交付版本；③ 一份启动、停止、重置和导入说明|让 C 在干净环境照说明启动。重复导入同一份作业只有一份；坏文件不会覆盖原作业；过期或已撤回的作业在重启后仍不能播放|
|B 负责学员操作的网页|frontend/，包括页面、按钮、浏览器测试和前端依赖文件|① 可以操作的练习页；② 能交给 A 打包的网页文件；③ 一份目标设备上的自测结果|点唱词能选句、听前导、慢放和循环；能录、停、对听、重录和删除；拒绝麦克风仍可听，离页停止录音；重开能接续，也能清除待练记录|
|C 负责唱段和音频工具|audio/、samples/、qa/，包括样本说明、音频检查和整套软件的试用记录|① 一段获准演示的 WAV 和三句唱词时间表；② 一个能检查音频和时间表的小工具；③ 演示步骤和测试结果|请老师校订、另一人复核，记下来源、署名和许可期限。工具能通过好样本，指出哪一句越界，也能拒绝坏音频。最后用交付版亲自练完一次|

各人维护自己目录里的依赖和测试。A 负责最后合并；B 决定页面怎样提示和恢复；C 负责时间表是否符合示范唱法。真实素材和许可凭证按许可范围交接，Git 只收允许提交的样例。

## 只约好两次交接，就能分头开发

1. **C 交给 A 一份作业包。** 包里有录音、唱词、每句从哪儿开始听、何时开口、到哪儿结束，以及署名和许可信息。C 的工具检查文件和时间，A 的程序检查授权、保存并发布。发布后，学员每点一次播放，都由 A 的服务提供音频；C 的工具只在导入时运行。
2. **A 交给 B 一个作业地址。** B 打开这个地址，能拿到唱词、时间和音频地址。比如第二句从第 4 秒听过门、第 5 秒进入乐句、第 8 秒结束，A 传给 B 的数字就是 4000、5000、8000 毫秒。B 负责按这些位置播放。学员录自己的声音由 B 在浏览器内完成，离开后释放，服务器只提供示范音频。

**第一天谁都可以先做。** 三人花十分钟看同一份三句样例。B 直接用样例画页面和试播放；A 用样例写导入与读取；C 用一段自制测试音写检查工具，同时联系老师。遇到数字或文件格式问题再查[接口约定及完整样例](API_CONTRACT.md)。改格式由 A 统一更新，告诉用到它的人。

## 五天交付表

|哪天|A 当天交|B 当天交|C 当天交|收工前一起做一次|
|---|---|---|---|---|
|第 1 天|从现有仓库开工，给 B 一个能打开的作业地址和三句样例|一页能显示三句唱词、点选当前句的网页|可读的测试音、检查工具入口，确认真实音频来源和复核人|B 从 A 的程序读出句单；A 能调用 C 的工具|
|第 2 天|能导入、提供音频和撤回作业的程序|原速、慢放、循环、录音和对听按钮|第一份经复核的三句作业包，附一个故意写错的时间表|导入真唱段，点每一句试听；换坏包，旧作业仍能打开|
|第 3 天|把网页和服务装在一起，处理过期、撤回和重启|做完复练接续、清除、拒麦和录音中断提示|用真实作业跑两遍，记录哪一步卡住；确认学员原声没有上传|从正式入口完成“听 → 录 → 对听 → 重开续练”，再撤回旧链接|
|第 4 天|修安装、存储和权限问题，留一个能回退的版本|在小屏、大字和键盘操作下试用，修误触、双声和提示问题|换干净环境试装，测坏音频、无许可、到期、重启|让没写网页的人照说明操作；把影响演示的问题当天分给负责人|
|第 5 天|定最终版本，交下载地址、启动说明及已知问题|用最终版本重测网页，交自测结果|用交付包和获准素材彩排，交演示步骤与测试记录|按下面四项逐项打勾，通过后由 A 发布|

## 合作时怎么少改同一份文件

- 每人从 GitHub 的 main 开自己的分支。一次只做一件事，做完发 PR（请队友检查并合并的请求），写清“改了什么、怎么试”。另一人看过，A 合并并打开作业试一次。
- 发现第二句播错，先让 C 查时间表，再让 A 查网页收到的数字，最后让 B 查播放器。查到哪一步出错，就由那一步的负责人修。需要代改时，在任务里写清接手人，避免两个人同时改。
- 早上各说今天交什么；下午留一小时把三份成果接起来。卡住半小时就发 GitHub Issue，写上复现步骤和需要谁帮忙。群里讨论，A 把当天结果写进[每日记录](DAILY_PROGRESS.md)，改过的约定写进[决策记录](DECISION_LOG.md)。
- 有人预计迟半天，先把已完成的分支、启动方法、剩下的一步交出来。A 忙不过来时 C 接整体验收，B 帮审；B 卡住时 A 协助修播放，C 复测；C 等素材时 A 帮联系老师，C 继续用测试音测程序。原素材授权赶不上，换获准的原创短句并复核。

## 最后四项检查

- [ ] **能交给别人运行。** 在干净环境用交付说明启动软件、导入作业、看到署名，演示机本地就能练。
- [ ] **能完整练一句。** 三句都能选；指定句慢放、循环三遍不串句；录音与示范交替播放不重叠；关掉重开能回到待练句。
- [ ] **出问题也有结果。** 拒麦能继续听；中断能重录；录音可删除、离页后释放，检查网络请求没有学员原声；坏包被拒收；撤回或过期后旧地址无法再取音频。
- [ ] **演示结果有依据。** C 记下样本、设备、软件版本、实际结果和复测人。教师标定的入点用于提示开口；自动拆句、连续跨版本对齐、自动评分沿用原研究计划，待样本和评测通过后再开发。[完整功能与验收](../01-产品定义与技术预研/功能与验收.md)
