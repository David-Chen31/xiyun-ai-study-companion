## 从录音到学员练习

1. 老师提供获准使用的示范和句表，独立复核人确认署名、句界和入点。A 核许可和复核记录，把待导入包暂存于私有区。
2. A 将示范和句表通过 HTTP 发给 C。C 验证文件、测量实际时长及声道、检查句界，返回结构化结果。失败由 A 保留原因供修订；成功后 A 再查授权并一次性保存文件引用和已发布作业快照。
3. B 向 A 取作业、按句播放示范。待练位置在浏览器保存，学员原声只在页面内存中回听。A 撤回或许可到期后阻断新取流。C 暂停服务时，已发布的作业仍能练习。
4. 平台阶段由 A 管分析任务、修订和授权，C 返回带输入修订及算法版本的候选，老师可逐条采纳或改写。修改输入即重新审校；候选不得直接成为已发布内容。

## 全部功能由谁承接

“本机”指浏览器独立完成，无需新增后台接口。A 对所有业务接口、数据落库与集成负责；C 对所有分析算法及其离线评测负责。平台/研究行表示已指派未来负责人，启动时须另外冻结该功能接口。

|功能|A 业务后台职责|C 技术职责|B 用户操作 / 交付阶段|
|---|---|---|---|
|F01 作业入口|课程读取、署名、授权|无需计算|直达作业；五天|
|F02 逐句听练|提供句表和音频分段取流|验证时轴|原速、慢速、前导、循环；五天|
|F03 录后对听|只供应示范|无需接收原声|本机录、听、删；五天|
|F04 进度|提供稳定快照与课项 ID；平台再做账号同步、去重、删除|无需计算|本机待练和清除；五天|
|F05 素材入库|导入、许可、私有存储；平台再加上传与任务|解码检测、媒体参数；平台增加格式转换|五天本地导入；平台提供上传进度|

## 三人怎样一起交付

- A 独占 backend/、业务数据库、根配置、启动/发布脚本和 contracts/；B 独占 frontend/ 和页面设计；C 独占 ai_backend/、算法依赖、样例说明及评测。各自维护目录内锁文件与测试。A 负责素材合作及授权，C 做技术样本，老师完成专业复核。
- 第一天确认机器、工时、授权与复核人。建议现场栈为 TypeScript 网页、Python HTTP 服务和 SQLite。A、B、C 用接口样例分别启动，再确认一次成功和失败请求，记录冻结提交。每人从最新 main 开 feat/backend-*、feat/frontend-* 或 feat/ai-* 分支。一次任务一个 Issue 和小 PR，写改动、影响、验证及版本。至少一位非作者审，A 合并并从作业入口复测。
- 每早十分钟说今天的成果、需要谁帮忙。下午预留一小时集成：D1 两条真实 HTTP 连通；D2 用已审示范导入并播放；D3 正式入口完成复练和撤回；D4 验证异常及换机安装；D5 从交付包复跑并签发。C 交服务测试，B 交浏览器测试，A 汇总业务测试与最终结果。
- 卡住半小时就在 Issue 放请求、返回和复现步骤，继续用样例开发。跨目录先约所有者；临时接手时登记唯一接手人。页面布局由 B 定、表与事务由 A 定、分析方法由 C 定。改变用户动作、数据流向、接口、权限、评分或放行标准时，三人评估影响，A 写回[决策记录](DECISION_LOG.md)，更新样例、设计及测试后合并。
