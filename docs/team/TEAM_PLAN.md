# 团队分工与研发协作计划

**第五天要演示的任务**：在一台干净的演示电脑启动软件，内容负责人导入一份经独立复核的三句作业，学员打开作业、听过门、循环指定句、录下自己、交替回听并重录，次日打开同一链接能回到待练句。撤回作业后旧链接停止取流。这个本地可运行的软件同时可作为第一阶段验证工具。

## 起点与承诺边界

2026-11-20 检查了含隐藏项的项目根目录、文件清单和 Git 状态。根目录只有 AGENTS.md 和 docs/，Git 报告当前及父级均非仓库。规划前 docs 有 18 份 Markdown，包括阶段一的市场、需求、流程、低保真、声学研究与初步契约，阶段二的候选视觉、数据库与架构，阶段三的交付测试，以及流程、索引和审查记录。未见源代码、构建配置、锁文件、数据库、已授权音频、测试或可启动服务；没有可核实的已实现功能或代码级耦合。[现有索引](../README.md) · [研发流程](../产品设计与研发协作流程.md)

已形成的需求基线为教师校订、按句听练、本机录后自听和复练接续。H1 主动复练、H2 持续提供合法内容尚待取证，两周实验跨出五天窗口。五天完成现场验证软件，面向班级的部署和 F01–F07 完整平台继续按原门槛决策。本轮 F01 直达作业、F02 听练、F03 对听、F04 本机进度，F05–F07 用本地导入、人工句表、独立复核记录和撤回来实现。保留来源和署名。服务器只监听回环，浏览器与 API 同源，录音使用 localhost。跨设备公网分享、账号同步、教师时间轴、云桶和上传后台留待平台阶段。[功能清单](../01-产品定义与技术预研/功能与验收.md) · [需求验证](../01-产品定义与技术预研/验证与待决策.md)

既有候选是 TypeScript 网页、Python HTTP、关系数据库及私有媒体存储。针对单机建议 Vite + TypeScript、FastAPI、SQLite 与 Web 根目录外的私有文件夹；静态构建由 A 的服务统一托管。未选定或安装软件包。C 用 Python 标准库处理 PCM WAV，人工划句和教师入点只驱动播放提示。自动拆句、跨版连续对齐、学员入点评分、ASR 和模型训练均留待有许可的数据与盲测。以后如需同句异唱，先用两份独立修订的人工作品对应关系。演示当日不依赖外部模型、密钥或网络推理。

## 三人所有权与交付边界

以下路径均为开工建议。每行首位为唯一写入负责人，协助者做评审、测试或提供样例。跨区修改先在 Issue 指定文件、约定接手人和时段。依赖锁文件归其目录所有者，公共 UI 仅在前端复用。

|模块 / 主责（协助）|写入范围与开发任务|边界、依赖与对外接口|交付物及过关条件|
|---|---|---|---|
|课程服务 A（C）|backend/，含数据库模型、迁移、Python 依赖、CLI、私有媒体适配与后端测试|调用 C 的纯处理函数，向 B 提供 HTTP；所有 SQL、许可检查、事务、Range 均由 A 实现|导入及撤回命令、课程与取流接口；重试不重复发布，撤回和过期阻断旧链接|
|集成与发布 A（B、C）|根配置、启动脚本、.github/、共享 contracts/ 样例、团队计划及契约、发布说明|征求消费者意见后合入契约；由 B 提供静态构建，C 提供许可样本|空环境可按说明启动；合并后冒烟通过并标记演示版本|
|作业网页 B（A）|frontend/，含 package 与锁文件、组件、Mock、录音状态机、浏览器测试|仅用 HTTP/浏览器媒体 API；不写 SQL、解码器和服务端模型|一页完成选句到对听再练；拒麦降为听练，离页释放原声；小屏可点、键盘可操作|
|音频与内容包 C（B试听、A验收）|audio/ 含独立 Python 包、依赖、测试及生成夹具；samples/ 仅存允许入库的样例及说明|输入本地 WAV、人工句表，输出标准校验结果；无 HTTP、DB 或前端依赖。私有原件与许可凭证单独交接|一段三句及校订出处，合成边界测试音，损坏/越界反例；可单独运行验证器|

预防设计耦合：媒体零点只认原 WAV 的整数毫秒；B 消费服务端句界而不重新估算；C 从不回调 A；同一快照由 A 原子发布。调用链为网页 → 课程服务 → 音频模块，服务拥有存储。C 写独立回归与内容包，B 自测交互与录音，给 A 留出集成时间。每日每人按约 5 小时主任务、1 小时评审配对、1 小时联调与修复估算；D1 按实际可用工时缩减范围。

## 启动会与独立开工

A 在首小时确认三人的可用工时、Git/PR 熟练度、A 的 Python/SQL/部署经验、B 的 TypeScript/浏览器录音经验、C 的 Python/音频与标注经验，另核实老师、独立复核人、演示设备与系统、音频许可、仓库 URL 和权限。在[决策记录](DECISION_LOG.md)填实际结论。技能不匹配时先交换主责及备援，再冻结文件边界。三人走查同一个成功样例和撤回失败样例后确认[接口契约](API_CONTRACT.md)。

B 用契约 JSON 和本地测试 WAV 起 Mock；A 用固定校验返回及三句样本写 API 测试；C 用合成 WAV 测字节和时间边界，同时准备真实可用样本。三条线可同时启动。合成音只能验流程；演示学唱需要明确授权的歌声与复核句表。

## Git、工具与每日协调

- main 保持可启动。A 首次建基线后保护 main。成员每日从最新 main 开短分支 feat/frontend-主题、feat/backend-主题、feat/ai-主题 或 fix/主题；按闭环切小 PR，当天审合。提交采用 type(scope): 动作，例如 feat(audio): 校验乐句末端。一次提交只做一项可验证改动；用 git add 指定路径并检查 git diff --cached，排除原声、私钥、构建产物和本机库。
- PR 关联 Issue，写明任务结果、涉及目录和契约版本、验证命令/设备/截图、限制与回退方式。每个 PR 至少一位非作者审核；A 的 PR 由 B 或 C 审，A 最终合并。合并前同步 main，冲突交文件所有者解释意图，分支上解决并复跑测试。合并后 A 检查启动、开课和试听；破坏 main 时用 revert PR 撤销后重验，不改写共享历史。
- GitHub Issues 是任务及缺陷状态唯一来源；每项有唯一负责人、依赖、验收和截止日。Projects 直接展示这些 Issues，列为待做、进行、阻塞、评审、完成。GitHub PR 是代码变更与审核入口。[GitHub Projects 说明](https://docs.github.com/en/issues/planning-and-tracking-with-projects/learning-about-projects/about-projects)
- 飞书群快速讨论；飞书文档保留会议纪要、决策背景与共识。A 将正式结论编号写回 DECISION_LOG 并链接纪要，涉及行为同步改契约/PRD 与 Issue。可选 Figma/FigJam 仅用于有歧义的流程或页面，B 把最终设计链接放回任务。仓内契约为编码依据。
- 早会 10–15 分钟，各报昨日结果、今日交付、阻塞、所需协助。开发中先查契约；跨区先找负责人。阻塞超过 30 分钟即在 Issue 给复现、影响与所需决定，群内提醒，改做夹具或其他独立项。晚间 B/C 在自身 Issue 留产物、测试与延期，A 汇总[每日记录](DAILY_PROGRESS.md)，检查进度、冲突、契约变化和次日调整。共享日报和决策日志由 A 一人落笔。

## 风险与接管

|等级 / 触发|影响|预防|应急动作|负责人|
|---|---|---|---|---|
|高：模型输出不稳定或没有入点金标|误导学员|只使用人审锚点|关闭自动候选，展示教师提示及对听；不报分|C|
|高：客户端字段、单位与契约不符|定位错句|同一 JSON 与毫秒反例测试|暂停相关合并，A 召集双方核对样例并发兼容修订|A|
|高：真服务取流或录音失败|主路径阻断|D1 真 HTTP、D2 真音频，localhost 测麦克风|B 分别测试浏览器与 API，A 修取流；锁定已验证设备再复测|B|
|中：分支争改共享文件|合并拖延|独占目录，小 PR 每日合入|所有者配对解冲突；已破坏 main 则回退|A|
|高：主责预估晚半天或缺席|依赖方停工|每日推分支，Issue 留启动命令、最后可用提交与失败用例|按下述接管规则转移一个最小交付项|A|
|中：外部 API、模型或包源中断|安装或分析失败|核心无云推理；预装锁定依赖|忽略模型服务，在验过的离线环境启动|C|
|高：许可缺失、音质太差或句界未经复核|不能展示真实唱段|D1 核查素材、范围、到期与复核人|换为明确获准的自录原创短句并复核；只有合成音时仅报工程演示|C|
|高：D5 仍崩溃或原声泄露|无法放行|D3 实件闭环、D4 留候选|回退候选并重测；隐私或权利问题仍在即停用受影响包|A|

接管顺序：A 缺席由 C 临代集成并由 B 审核；B 延期由 A 接手最小播放/录音修复，C 承接回归；C 延期由 A 接手已审固定包的导入，B 代跑样本测试。先由代理队长在 Issue 指定唯一临时所有者、移交分支 SHA、剩余检查与截止时间，原主责暂停写该文件。恢复时同样登记归还。优先取消装饰、自动分析与扩展设备支持，保留主设备、版权、撤回和原声隐私检查。
