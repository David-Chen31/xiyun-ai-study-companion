# 产品设计与研发协作流程

后续 Codex 工作从项目索引定位当前阶段，再按本规范处理任务。项目当前处于阶段一。文档已有、原型可点击或接口可调用，均不能代替对应阶段的验证记录。

## 一、产品定义与技术预研

1. 从市场及竞品着手，观察老师最近一次布置作业和学员最近一次练习，记录现用替代工具、耗时、求助与退出原因。将公开事实、观察和假设分别标明。
2. 在 PRD 内先写用户画像、痛点、定位与核心价值，再按用户结果写需求。在功能清单内维护唯一的 F 编号、MVP 边界和验收示例。
3. 从入选任务整理信息层级，画核心路径，再用关键页面低保真走查。产品与前端共同检查手机录音、播放中断和次日复访。优先做能回答研究问题的最小原型。
4. AI 与后端并行做可行性预研，明确数据许可、人工基线、误差和弃判。以同一份作业拟定逻辑实体、权限、输入输出及失败行为。
5. 产品负责人将 H1 自主复练、H2 教师供给的实际人数、素材、结论和保留的核心流程记入《验证与待决策》。证据不足时裁剪或重测。通过后才深化入选任务；F08 等研究项另过各自门槛。

## 二、产品设计与技术架构深化

设计与前端先细化目标任务的操作顺序、等待、空、拒权、中断及恢复，再为核心页面制作高保真原型，提取该流程需要的视觉规则。后端同步细化数据库、API、权限、事务与部署边界。AI 负责人只为进入本轮的能力确认输入条件、延迟、输出和失败回退。

联合评审用同一份作业依次演示正常和失败路径。每个可见状态都应找到触发事件、真实字段或本机状态、恢复动作及验收例。例如撤权由服务端拒绝新取流，前端停播并保留原因；路由变化使入点校准失效，界面退回自听。前端负责设备交互、可访问性和状态恢复。字段缺失或体验不可实现时一同修订设计与契约。把结论记回原文档，标明已确认的 F 编号与未决问题，作为相应 Sprint 的入口。

## 三、以完整任务组织 Sprint

开始前，Codex 与参与者逐项核对相关 PRD 和 F 编号、页面与异常状态、API 示例与数据结构、验收用例及测试条件。每个 Sprint 写下一句可演示的用户结果和关联的 A 编号，切分示例见《交付与测试》。

前端以约定的成功及失败样例先行开发，同时后端实现相同契约，尽早换用真实服务联调。涉及 AI 的功能同时走查可信输出、弃判与关闭功能后的人工路径。变更字段、时钟、权限或交互时同步更新受影响文档和样例，再继续集成。

结束前用真实入口演示闭环，对照页面设计检查一致性，执行功能和回归测试，再在目标设备上检查任务完成、拒权恢复与可访问性。在交付记录写下设备、样本修订、预期与实际、缺陷、责任人及复测结果；更新 PRD、页面、契约或验收中发生变化的部分。阻断闭环的问题修复并复测后方可计为完成。

## 四、用真实使用结果持续优化

已有功能的测试、试用观察或支持记录暴露问题时，记录受影响任务、复现条件、频次和后果，按影响排序。依次细化剩余页面、修正视觉与交互不一致；多个已实现页面反复使用同一模式时，再抽取组件并验证键盘、大字及移动端行为。用同一任务复测改动前后的完成率、耗时或求助次数，记录保留、调整或回退的决定。需要改变产品目标时回到 PRD 和验证记录。

每项决定只在其负责文档维护一份，其余位置引用。第四阶段可随已交付的闭环启动，首次出现真实优化任务时再建立对应记录。
