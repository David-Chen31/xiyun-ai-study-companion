## 已完成的 D2 检查

- 从磁盘读取完整 WAV 文件，而不是只相信 metadata 中填写的时长。
- 用实际帧数、采样率计算 `duration_ms`，不足 1 毫秒向下取整。
- 核对采样率、声道数、16-bit PCM 格式、帧数据完整性及 10 分钟/100 MB 限制。
- 补强 RIFF 长度、数据块截断、半个单/双声道采样帧及错误帧宽/字节率检查；额外 JUNK 等元数据块允许存在。
- 修正恰超过 600 秒一帧的音频被毫秒取整掩盖的问题；超限按精确帧数判断。
- 使用三句句表验证 `lead_ms`、`start_ms`、`entry_ms`、`end_ms` 的边界。
- 验证第三句 `entry_ms=null` 可以通过，表示只听练。
- 验证第三句 `end_ms=12001` 返回 HTTP 层使用的 `422 INVALID_BOUNDARY`，字段为 `phrases[2].end_ms`。
- 缺失 `entry_ms` 返回 400 和准确字段，显式传 `null` 允许听练，避免缺字段触发 503。
- 本机检查命令可保存帧数、位深、SHA-256、耗时和来源说明；失败记录保留请求编号。它不自动判断样本授权或教师复核是否有效。

## 可复现命令

在仓库根目录运行：

```powershell
python -X utf8 -m unittest discover -s ai_backend/tests -t . -v

python -X utf8 -m ai_backend.d2_validate `
  --audio ai_backend/samples/demo_12s.wav `
  --metadata ai_backend/samples/success_three.json

python -X utf8 -m ai_backend.d2_validate `
  --audio ai_backend/samples/demo_12s.wav `
  --metadata ai_backend/samples/invalid_three_boundary.json
```

合法三句样例预期：`status=passed`、`duration_ms=12000`、`sample_rate_hz=16000`、`channels=1`、`phrase_count=3`。越界样例预期：`status=failed`、`code=INVALID_BOUNDARY`、`field=phrases[2].end_ms`。

## 当前实测结果

本次使用的是仓库中的程序合成 WAV：12 秒、16000 Hz、单声道、16-bit PCM。它用于验证软件读帧和边界逻辑，不是教师人声，也不代表专业句界已复核。

本次真实运行 `Ran 56 tests in 1.238s`，结果 `OK`。包含磁盘样例校验、44.1/48 kHz 双声道、坏包回归、本机报告和真实回环 HTTP 请求。文件超限测试用缩小的阈值验证拒绝逻辑，没有实际上传 100 MB；10 分钟边界使用真实帧数据验证。

报告 JSON 保存在 [reports/](reports/)：合成三句通过（192000 帧、16000 Hz、单声道、16-bit、12000 毫秒），第三句越界失败（q10、422、`phrases[2].end_ms`）。其中 `elapsed_ms` 记录本机运行耗时，不代表部署性能指标。

D2 的真实素材验收仍需要一份获准使用、由老师复核的三句 WAV 与对应句表；收到后，把文件放在受控目录，用同一条 `d2_validate` 命令运行，并记录实际参数、耗时、样本来源和失败原因。不要把私有或未授权音频提交到仓库。

## A/C 联调验收

1. A 在同一台机器启动 C 服务（默认 8300），双方配置一致的内部令牌。
2. A 从业务后端发送真实三句课包，核对 request_id、revision_id、时长、声道和句数。
3. 保持第三句 `entry_ms=null`，应通过检查，A/B 保留听练能力。
4. 构造副本，将第三句结束时间改到音频之后，应返回 422 和 `phrases[2].end_ms`。
5. 记录样本修订、来源、复核记录与实际返回结果。完成后才将 D2 标为已验收。

真实素材与上述 A 进程联调当前均尚未进行；现有 HTTP 测试是 C 的本机测试。
