# C 的临时检查接口 c-inspect-draft-20261121

状态：C 独立开发阶段可运行草案，未与 A 业务后端对接，不视为团队冻结契约。

本轮依据 A 的最新安排：C 先自行准备基础素材，参数和返回格式暂由 C 定义，待后续统一接口。为减少迁移，本版继续使用已有 inspect 草案的路径和字段；只在 C 目录维护本说明，不修改 A 所有的公共契约、业务后端、数据库或根配置。

## 当前能力

读取 16-bit PCM WAV 的实际采样帧、采样率和声道，核对时长、格式完整性及句表时间范围，返回检查结果或具体错误字段。它不是语音识别、自动分句、入点检测或演唱评分服务；当前不调用外部模型。

## 调用

默认地址：`POST http://127.0.0.1:8300/internal/v1/inspect`。

请求头：`Authorization: Bearer <内部令牌>`。本机环境变量为 `AI_BACKEND_TOKEN`；A 接入时双方约定正式值，令牌留在服务端。

请求体采用 `multipart/form-data`，客户端提供 Content-Length：

| 字段 | 类型 | 含义 |
|---|---|---|
| `audio` | 原始文件字节 | 16-bit PCM WAV，单/双声道 |
| `metadata` | UTF-8 JSON 文本 | 请求编号、修订编号与句表 |

metadata 必须有 `request_id`、`revision_id` 两个非空字符串，以及非空 `phrases` 数组。

```json
{
  "request_id": "basic-speech",
  "revision_id": "basic-r1",
  "phrases": [
    {"id":"window1","text":"语音技术窗口一","lead_ms":0,"start_ms":0,"entry_ms":0,"end_ms":3600},
    {"id":"window2","text":"语音技术窗口二","lead_ms":3600,"start_ms":3600,"entry_ms":3600,"end_ms":7300},
    {"id":"window3","text":"语音技术窗口三","lead_ms":7300,"start_ms":7300,"entry_ms":null,"end_ms":11000}
  ]
}
```

时间为原始 WAV 零点起的整数毫秒。`id` 为非空且不重复的字符串，`text` 为字符串；`lead_ms`、`start_ms`、`end_ms` 为整数，`entry_ms` 必须提供，值为整数或 null。布尔值不作为整数。null 表示缺乏入点标注，可用于听练。

检查关系：`0 ≤ lead_ms ≤ start_ms < end_ms ≤ duration_ms`，非空入点满足 `lead_ms ≤ entry_ms < end_ms`。本版只检查每句范围，不强加句间连续、不重叠或语义切分要求。

当前大小上限明确按 `104857600` 字节（100 MiB）实现，时长按精确帧数限制为 600 秒；整数毫秒时长向下取整。若团队最终采用十进制 100 MB，将同步调整限额、文档和测试。WAV 限一个 fmt/data 块，允许完整附加元数据块。

## 成功与失败

成功 HTTP 200：

```json
{"request_id":"basic-speech","revision_id":"basic-r1","processor_version":"wav-inspect-1","duration_ms":11000,"sample_rate_hz":44100,"channels":2,"phrase_count":3}
```

把第三句 end_ms 改为 11001 后，HTTP 422：

```json
{"request_id":"basic-speech","code":"INVALID_BOUNDARY","message":"结束时间超出音频","field":"phrases[2].end_ms"}
```

| HTTP | code | 含义 |
|---|---|---|
| 400 | INVALID_INPUT | 字段缺失、类型/JSON/表单不合法 |
| 401 | INVALID_TOKEN | 令牌不正确 |
| 413 | TOO_LARGE | 文件或时长超限 |
| 415 | UNSUPPORTED_AUDIO | 格式不支持、文件损坏/截断 |
| 422 | INVALID_BOUNDARY | 时间范围错误或句 ID 重复 |
| 503 | ANALYSIS_UNAVAILABLE | 未预期的内部错误，可由调用方重试 |

错误含 `request_id`、`code`、`message`，可定位时附 `field`。认证前或 JSON 无法解析时 request_id 为 null。正常回复回传原 request_id/revision_id；A 之后需核对它们，避免旧结果覆盖新修订。

## 运行与接入示例

在项目根目录启动：

```powershell
$env:AI_BACKEND_TOKEN = "c-local-demo-token"
python -X utf8 -m ai_backend --host 127.0.0.1 --port 8300
```

另开窗口发送本包公开语音：

```powershell
python -X utf8 -m ai_backend.replay --token c-local-demo-token --audio ai_backend/samples/basic/jfk-speech.wav --metadata ai_backend/samples/basic/speech.json
```

Python 调用方可复用下例，也可以独立构造相同的 multipart 请求：

```python
import os
from pathlib import Path
from ai_backend.replay import send_inspect

status, result = send_inspect(
    "http://127.0.0.1:8300", os.environ["AI_BACKEND_TOKEN"],
    Path("ai_backend/samples/basic/jfk-speech.wav").read_bytes(),
    Path("ai_backend/samples/basic/speech.json").read_bytes(),
    timeout=30,
)
print(status, result)
```

同一请求重复调用会重新计算，不产生发布或数据库副作用。音频只在内存处理，不保存到业务库、不写临时音频。报告命令的文件输出与服务响应分开，HTTP 结构不受测试报告字段影响。

后续统一时，与 A 一次确认地址、传输方式、字段、时间单位、限额、错误码、令牌配置和超时；若有改动，同时提供新旧请求示例。当前独立 HTTP 测试通过不能写成“A 业务后端已联调”。
