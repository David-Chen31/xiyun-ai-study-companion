## 一、实现要点与自主决策

按 C 任务书的自主权（分析库与算法内部实现由 C 决定）做了以下选择，均已在本目录文档化：

1. **零依赖**：`wave` + `http.server`（ThreadingHTTPServer）+ 自写二进制安全 multipart 解析。A 无需 pip 安装即可启动。
2. **时长换算**：`duration_ms = 实际帧数 × 1000 ÷ 采样率`，向下取整为整数毫秒（保守，不夸大音频长度）。以实际读到的帧数为准，头声明与数据不符按截断拒绝（415）。
3. **无临时文件**：音频全程内存处理（≤100 MB 上限内），比契约"处理完释放临时文件"更严格，无残留风险。
4. **错误码映射中契约未明说的两处**（需 D1 冻结时与 A/B 确认）：
   - 时长 >10 分钟 → `413 TOO_LARGE`（与文件超限同码，field=audio）；
   - 重复句 ID → `422 INVALID_BOUNDARY`（field=phrases[i].id）；空数组/结构类型错误 → `400 INVALID_INPUT`。
5. **零帧音频**按 `415 UNSUPPORTED_AUDIO` 拒绝（契约未定义，属坏音频）。
6. **401 前先丢弃请求体**再回包并关闭连接，避免 A 的客户端在 Windows 上收到连接重置而读不到错误 JSON。
7. 令牌用 `hmac.compare_digest` 常量时间比较；未配置令牌拒绝启动；绑定非回环地址打印警告（契约要求仅回环）。
8. 错误响应在 metadata 可解析时始终回传 `request_id`，便于 A 对账；未预期异常统一 `503 ANALYSIS_UNAVAILABLE`。

## 三、服务级重放（真实 HTTP，端口 8300，令牌 dev-token-123）

启动：`python -m ai_backend --port 8300 --token dev-token-123`

样例 WAV 实测：192000 帧 × 16000 Hz × 1 声道 × 16-bit，文件 384044 字节，恰为 12.000 秒。

1. 成功（`success.json`，q7）→ **HTTP 200**：

```json
{"request_id":"q7","revision_id":"r1","processor_version":"wav-inspect-1","duration_ms":12000,"sample_rate_hz":16000,"channels":1,"phrase_count":1}
```

2. 三句课包（`success_three.json`，q9，第三句 entry_ms=null）→ **HTTP 200**，`phrase_count=3`，`duration_ms=12000`。
3. 越界（`invalid_boundary.json`，q8，end_ms=13000）→ **HTTP 422**：

```json
{"request_id":"q8","code":"INVALID_BOUNDARY","message":"结束时间超出音频","field":"phrases[0].end_ms"}
```

4. 错误令牌 → **HTTP 401**：`{"request_id":null,"code":"INVALID_TOKEN","message":"内部令牌缺失或不正确"}`
5. curl 重放（README 中的命令原样执行）→ **HTTP 200**，输出与第 1 条一致。

重放客户端退出码：200→0，非 200→1，便于脚本化验收。测试后服务已停止。

3. **A 进程真实调用**：请 A 从自己的后端进程（非浏览器）发一次成功 + 一次 422 请求，核对回传 request_id/revision_id 与草稿对账逻辑；可直接复用 `ai_backend/replay.py` 的 `send_inspect`。
4. **30 秒超时语义**：C 为同步处理，12 秒样本毫秒级返回；A 侧按契约 30 秒超时按服务不可用处理并用同一包重试，需联调验证一次超时模拟。
5. **超大文件行为**：>100 MB 时 C 依据 Content-Length 提前回 413 并关闭连接，A 的客户端可能在读响应前遇到连接中断，建议 A 发送前先本地检查文件大小；联调时确认。
6. **D2 真实课包**：本服务目前只验证了合成样本；老师复核的三句真实 WAV（可能双声道、44.1 kHz 等）需 D2 联调实测，届时请 B 试听第二句区分人工标错与换算错。
7. **健康检查端点**：契约未定义，C 未擅自添加；若 A 启动编排需要探活接口，三人确认后补。

## 五、已知限制

- 仅支持 16-bit PCM WAV（契约范围）；压缩 WAV、浮点 WAV、其他容器一律 415。
- 未做请求编号去重/幂等（D3 范围）；同一 request_id 重复提交会重复计算，无副作用。
- 单机单进程，无并发压测；现场导入频率低，ThreadingHTTPServer 足够，D4 换机时复测。
